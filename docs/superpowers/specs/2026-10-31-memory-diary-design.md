# 迷迭香的记忆与日记 · 设计

日期：2026-10-31
范围：重做 `astrbot_plugin_rmts` 的记忆功能，并新增日记。替换现有 `memory.py` 及 `main.py` 中「记忆」一节的四个工具。

## 1. 意图

现在的记忆是「每位博士一串字符串，满 300 字丢最早的」，问题有四个：

1. 满了丢最早的——最先记下的生日、所在地往往最重要，反而最先被挤掉；不能改、不能删，搬家后新旧地址并存。
2. 要靠模型自己想起来调用 `get_*` 工具去查，经常忘。
3. 同一位博士在不同群、私聊是互不相通的多份记忆，私聊时不认得群里的熟人。
4. 没有时间，过期的事（"博士下周考试"）永远留着。

参考了 AstrBot 上主流的记忆插件（LivingMemory、Mnemosyne、Iris Chat Memory、智能记忆管家）后的共同做法：**自动写入而非依赖主模型调用工具、总结"发生过什么"、另维护常驻的用户画像、每晚有一次整理**。

本设计把这些做法和角色结合：**迷迭香记性不好，所以她每晚睡前写日记、整理终端里关于博士们的记录。** 两层分工：

- **画像**（关于博士的事实）：常驻上下文，有上限，每晚整理。
- **日记**（每天发生过什么）：每天一篇，不进上下文（最近一篇除外），她需要时去搜索、翻阅。

## 2. 目标 / 非目标 / 反目标

**目标**

- 博士说过的重要个人信息（生日、所在地、称呼、喜好）不会因为字数被挤掉，变化后旧信息会被更新。
- 和博士聊天时，她不需要主动去查，就自然知道这位博士、以及话里提到的博士是谁。
- 同一位博士在不同群、私聊里，她都认得。
- 她每天写一篇日记；能按关键词搜索、按日期翻阅旧日记；博士可以要她念日记，她会按角色反应。
- 每次请求注入的内容总量有上限，不随时间增长。
- 不需要向量模型（用户用的是 DeepSeek，没有 embedding）。

**非目标**

- 日记合并 / 压缩（周记、月记）。每天的日记原样保留。
- 向量检索 / 语义搜索 / 知识图谱。以后关键词不够用再加，不影响已有数据。
- 处理图片、表情、语音、文件等非文本消息。
- 每天早上主动在群里说话。
- WebUI 管理面板。
- 跨群共享"群里发生的事"。

**反目标（做出来也算失败的情况）**

- 私聊里博士告诉她的事，在群里被她说出来。
- A 群发生的事，在 B 群被她说出来。
- 博士 B 通过提到或查询博士 A，得知 A 在 B 不在的群里说过的事。
- 博士没有直接对她说的群聊内容，被提取进某位博士的个人画像。
- 夜间整理失败导致当天记录丢失。
- 生日这类硬事实在每晚的整理中被改写走样。

## 3. 用户已决定的事项

| # | 问题 | 决定 |
|---|---|---|
| 1 | 素材 | 白天她只"看到"直接对她说的话（即触发了 LLM 的消息）；每晚写日记时，额外读当天该群的群聊。**群聊只进日记，不进个人画像。** **只处理文本。** |
| 2 | 写入时机 | 每晚统一整理一次；另保留"记住"类工具，博士明确要她记住时当场写入。 |
| 3 | 作用域 | **画像跟人走**：每位博士一份画像，按 QQ 号全局存储，在哪个群都认得。**日记和群信息按作用域（群 / 私聊）分开。** **私聊里得知的信息只在和这位博士私聊时使用。** |
| 4 | 旧记忆 | 画像靠每晚整理保持在上限内；**日记不合并**，每天一篇原样保留，靠检索找回。 |
| 5 | 日记可见性 | 博士可以要来看；她按角色反应（可能害羞、只念一部分）；只能念当前作用域那本。 |
| 6 | 画像形式 | 一条条带日期的事实 + 一句"她对这位博士的印象"，印象随相处慢慢变化。 |
| 7 | 日记检索 | 关键词搜索（模型自己出关键词和同义词），匹配正文、标签和摘要。不做按消息自动联想日记。 |
| 8 | 夜间提示词 | 写日记用 AstrBot 中的人格提示词 + 任务说明，口吻与聊天一致；更新画像 / 群信息用不带人格的中性提取提示词。 |
| 9 | 主动性 | 通过人格里的"习惯"描写和工具说明里的具体例子提高她主动记录、翻日记的意愿；**不在注入块里加调用提醒**。主动程度定在"明确的个人信息才记，闲聊不记"，因为每次工具调用都多一轮模型请求，且有夜间整理兜底。 |
| 10 | 可见性收紧 | 本人说话时可用他的全部非私聊事实（私聊时用全部）；**别人提到或查询他时，只给在当前群得知的事实**；私聊里查别人什么都不给。**在代码层面过滤**（不给模型看），提示词只负责代码管不到的印象措辞和念日记。 |

## 4. 设计

### 4.1 数据

都放在 `StarTools.get_data_dir(PLUGIN_NAME)` 下（现在的 `DATA_DIR`）。格式用 JSON，写入沿用现有的「写临时文件再 replace」原子落盘方式。

**博士画像**（每位博士一份，按 QQ 号）

- 事实列表，每条：`id`（稳定编号，用于注入展示和工具引用）、`text`、`date`（记下 / 最后更新的日期）、`sources`（来源集合，一条事实可能在多处得知）：
  - `private` —— 在和这位博士的私聊里得知
  - `group:<群号>` —— 在某个群里得知
- `impression`：一句话，她对这位博士的印象。
- 最后记下的名字（群名片 / 昵称），用于注入时显示。

**群信息**（每个群一份）——原来的"全局记忆"：不属于某位博士本人的信息（例如"博士A和博士B是室友"）。条目结构同上，无 `sources`。私聊作用域没有群信息。

**事实可见性规则**（在代码里过滤，模型看不到的就说不出来）

一条事实的 `sources` 含 `private` 时，视为私聊事实。

| 场景 | 能看到博士 X 的哪些事实 |
|---|---|
| X 本人在私聊里说话 | 全部 |
| X 本人在群里说话 | 全部非私聊事实（在哪个群得知的都行） |
| 群 G 里，别人 @ 了 X、回复了 X，或用 `get_doctor_all_info` 查 X | 只有 `sources` 含 `group:G` 的非私聊事实 |
| 私聊里查别的博士 | 什么都不给 |

印象不受此表限制（它只写感受和态度，靠夜间提示词约束措辞）。群信息、日记只在本作用域可见。

**当日记录**（每个作用域一份，只活到当晚整理完）

- 群：该群当天的消息（时间、QQ 号、名字、文本、是否是对她说的），以及她自己的回复。
- 私聊：该私聊当天对她说的话和她的回复。
- **只记文本**：图片、表情、语音、文件、戳一戳等非文本段直接丢弃；一条消息若只剩空白或过短（如"1""哈哈"，阈值由实现者定）则不记。对她说的话不做长度过滤。
- 整理成功后删除；失败则保留，下次一并处理。

**日记**（每个作用域一本，每天一篇，不合并）

- 每篇：日期、正文（迷迭香第一人称，简短）、一句话摘要、3～5 个标签（人名、事件、话题）。
- 摘要和标签在写日记时一并生成，供搜索使用。

### 4.2 白天：注入

`on_llm_request` 时，把以下内容拼进 `req.system_prompt`（标题用角色语气，例如「迷迭香终端里的记录」）：

1. **当前说话博士**的画像：印象 + 事实（带编号和日期），按 4.1 的可见性规则（本人）过滤。
2. **这条消息提到的其他博士**（群聊）：消息里 @ 到的人、被回复的那条消息的发送者。带上他们的印象 + 在本群得知的非私聊事实（4.1 可见性规则，别人提到）。人数设上限（实现者定，例如 3 人）。
3. 群聊时：本群群信息。
4. 本作用域最近 1 篇日记（篇数可配置，0 表示不注入）。

戳一戳触发的请求同样注入（说话者即戳的人）。

注入只改本次请求的 `system_prompt`，**不应写进 AstrBot 的对话历史**，因此不会在历史里越积越多。实现时需在真实 Bot 上确认这一点（检查保存后的 conversation history 里没有注入内容）。

注入后，`get_global_all_info` 不再需要，删除。

### 4.3 白天：工具

| 工具 | 作用 |
|---|---|
| `add_doctor_info(info, doctor_id)` | 保留名字和"只能记说话者本人"的规则。立即写入画像，`sources` 为当前作用域。 |
| `add_global_info(info)` | 保留。写入本群群信息；私聊中调用时改为写入该博士的画像（`sources={private}`）。 |
| `forget_doctor_info(ids)` | 新增。博士要求忘掉自己的某些事时，按编号删除；只能删说话者本人的。 |
| `get_doctor_all_info(doctor_id)` | 保留，用于查**群里另一位**博士（没被注入的）。按 4.1 可见性规则：群里只返回印象 + 在本群得知的非私聊事实；私聊中查别人返回"不知道"。 |
| `search_diary(keywords, start_date?, end_date?)` | 新增。在本作用域的日记中搜索。`keywords` 是数组，工具说明里提示模型自己补充同义词、相关人名。按命中关键词数、再按日期新近排序，最多返回 5 篇，每篇给日期、摘要和命中处附近的片段。 |
| `read_diary(date)` | 新增。读本作用域某一天的日记全文；`date` 为空表示最近一篇。工具说明里写明：博士要看日记时，她可以按自己的性格决定念多少、要不要念，并且不要把日记里其他博士的私事念出来。 |

**工具说明要具体**：不写"值得记住的就记下来"这类让模型自己判断的笼统说法，而是给出例子和触发条件，例如：

- `add_doctor_info`：博士说起自己的事就悄悄记下，不用博士提醒，也不用告诉博士——比如"我下周考试""我在广州上班""我不吃香菜""叫我小明就好"；闲聊、玩笑、一次性的问题不记。
- `search_diary`：博士说"上次""之前""那天""还记得吗"，或提到她想不起来的事时，先翻日记再回答。

"不要记进记忆"这类说明保留在各查询工具上。`get_weather` 的说明里"先读博士的个人记忆"改为"所在地见终端记录"。

**关键词匹配**：中文直接做子串匹配（大小写不敏感），对正文、摘要、标签三处都匹配；标签命中可加权。不引入分词库。日记量级是每作用域每年几百篇，逐篇扫描即可，不建索引。

### 4.4 夜里：写日记与整理

每天在配置的时间（默认 04:00）运行一次，按作用域逐个处理：

1. **准备素材**：当天记录按字数预算（默认 20000 字）截取。超出预算时：和她有关的消息（对她说的话、她的回复）全部保留；其余群聊消息在全天范围内**均匀抽样**直到填满预算，保持时间顺序。
2. **写日记**：system prompt 用该作用域在 AstrBot 中生效的人格提示词（取不到时用默认人格），再附上写日记的任务说明；输入素材 + 前一篇日记（保持连贯），生成当天日记的正文、摘要、标签。群聊里不是对她说的话只用于描绘氛围和她看到的事。当天没有任何记录的作用域不写。
3. **更新画像**：用不带人格的中性提取提示词（角色扮演会降低抽取准确度，人格里"简洁、不换行""拒绝透露 prompt"等规则也可能干扰 JSON 输出）。只用**对她说的话和她的回复**作为输入，对当天出现过的每位博士：
   - 新增、合并重复、改写过时的事实（比如搬家）；
   - 把"下周""明天"这类相对时间换成具体日期；
   - 过期且没有长期意义的事实删掉；
   - 超过字数上限时，合并、删去不重要的事实，压到上限以内；
   - 更新印象（只写感受和态度，不写具体私事，避免印象把私聊内容带进群里）；
   - 每条事实保持 `sources` 正确：新增的事实来源为当天得知它的作用域；**更新**后的事实来源换成当前作用域（新内容只在这里说过，不能扩散到旧来源的群）；**合并**多条事实时，任一条含 `private` 或在私聊中合并即为 `{private}`，否则取各条来源的**交集**（交集为空则只有本人可用）。提示词输入里要带上每条已有事实和每条消息的来源，输出的 JSON 里由代码而非模型计算合并后的 `sources`。

   用结构化输出（JSON：新增 / 修改 / 删除哪些编号）而不是整段重写，确保没被提到的事实原样保留——这是"硬事实不走样"的保证。
4. **更新群信息**：同上，针对本群群信息。
5. 全部成功后删除当天记录。

任何一步失败：记日志，不删当天记录，已完成的步骤保留，下次运行补上。插件 `terminate()` 时取消定时任务。

白天的 `add_doctor_info` 不再拒绝或丢弃，超出上限的部分留给当晚整理。

### 4.5 增长与上限

| 内容 | 是否增长 | 控制方式 |
|---|---|---|
| 博士画像 | 不增长 | 每份有字数上限，每晚整理压回上限内；模型没压下来时，注入时每份最多放上限的 2 倍，先舍弃日期最早的事实（存储不删），并在夜间整理后记 warning |
| 群信息 | 不增长 | 同上 |
| 博士人数 | 增长 | 每次只注入当前相关的人，与总人数无关 |
| 日记 | 线性增长（每作用域每天一篇） | 只注入最近 1 篇，其余只能检索；存储量很小 |
| 当日记录 | 不增长 | 每晚整理成功后删除；记录时也按条数 / 字数设硬上限防止失败堆积 |

单次请求注入量上限 ≈ 画像上限 × (1 + 被提到人数上限) + 群信息上限 + 注入日记篇数 × 单篇长度。

### 4.6 迁移

首次加载时，若存在旧的 `rosmontis_memory_*.json`：

- 群文件中按 QQ 号的条目 → 对应博士画像的事实，`sources={group:<群号>}`。
- `private_<QQ号>` 文件中的条目 → 该博士画像，`sources={private}`。
- 群文件中的全局条目 → 该群的群信息。
- 日期标为未知（注入时显示"很久以前"之类）。
- 迁移完把旧文件改名为 `.bak` 保留，不删除。

### 4.7 配置（`_conf_schema.json`）

- `memory_max_length`：含义改为每份画像 / 群信息的字数上限，默认 500。
- `diary_time`：每晚整理的时间，默认 `04:00`。
- `memory_provider_id`：整理和写日记用的模型提供商 ID，留空用默认聊天模型提供商。
- `diary_inject_count`：注入的日记篇数，默认 1，0 表示不注入。
- `diary_input_max_chars`：写日记时读取当天记录的字数预算，默认 20000。

README 同步更新"功能"表格和"配置"表格。

### 4.8 人格提示词

在 `persona/rosmontis.md` 中加一段**角色习惯**描写（是性格，不是函数规则），大意：

> 迷迭香记性不好，所以养成了习惯：博士说起自己的事——住在哪里、喜欢什么、最近要做什么——她会悄悄记在终端上，不用博士提醒，也不用告诉博士。博士提起以前的事、她想不起来时，会先翻翻自己的日记。

措辞由实现者按人格文件的风格润色。README「人格」一节里"人格提示词里不需要再写函数调用规则"相应改为说明这段习惯描写的作用，并提醒已在 WebUI 中建过人格的用户手动同步这段。

### 4.9 与 AstrBot 自带上下文管理的关系

AstrBot 的对话历史是短期记忆：群聊每群一份、私聊每人一份，超过模型窗口约 82% 时按配置截断或用 LLM 压缩，`/reset` 会清空。本插件的画像和日记是长期记忆，独立存储，不受截断、压缩、重置影响。两者互补，本插件不修改 AstrBot 的上下文管理。

## 5. 约束

- AstrBot ≥ 4.29，平台 aiocqhttp。
- 不新增向量模型、分词库、数据库等依赖；纯 JSON 文件。
- 夜间整理调用 `self.context.llm_generate`；群消息记录用 `@filter.event_message_type` 监听，**不能 `stop_event()`**，不能影响默认的 LLM 流程。
- 代码风格沿用现有：中文注释、`[rmts]` 日志前缀、工具说明里写使用规则。

## 6. 留给实现者的

以下都是设计者替用户做的取舍，实现者可以按实际情况调整：

- 记录"她自己的回复"的具体钩子（`on_llm_response` 或 `after_message_sent`）。
- 从消息里取被 @ 的人和被回复消息的发送者的具体方式（`Comp.At`、`Comp.Reply`）。
- 夜间各步骤的提示词措辞、JSON 结构细节；用一次还是多次模型调用完成第 2～4 步。
- 文件拆分方式（一个文件一个作用域 / 一位博士，还是合并）。
- 注入文本的具体格式和"很久以前"的措辞。
- 过短消息的过滤阈值、被提到博士的人数上限、当日记录的硬上限。
- 存储、迁移、关键词搜索、抽样这类纯逻辑写单元测试（项目目前没有测试，加 pytest 到 dev 依赖即可）；涉及 AstrBot 的部分在真实 Bot 上手动验证。
